# 构建与测试

## 构建

两个插件同法构建：目标 Java 21（`--release 21`），无第三方运行时依赖，仅 Paper/Folia API（`io.papermc.paper:paper-api:26.2.build.115-stable`，scope `provided`，仓库 `repo.papermc.io`）。产物：

| 模块 | 版本 | 产物 |
|---|---|---|
| FmKit | 1.1.2 | `FmKit/target/FmKit-1.1.2.jar` |
| FmShop | 1.0.0 | `FmShop/target/FmShop-1.0.0.jar` |

### 方式一：build.ps1（作者实际使用，免 Maven）

前提：本地 `.m2` 仓库里已有 paper-api 及其传递依赖的 jar（任何方式拉过一次即可，脚本把整个 `.m2` 的 jar 全部挂上 classpath）。默认取 `%USERPROFILE%\.m2\repository`，可用环境变量 `M2_REPO` 覆盖。

```powershell
cd FmShop   # 或 FmKit
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

脚本流程：收集 `.m2` 全部非 sources/javadoc jar → `javac --release 21 -encoding UTF-8` 编译 `src/main/java` 到 `target/classes` → 复制资源（FmKit：`config.yml`/`plugin.yml`；FmShop 另加 `prices.yml`）→ `jar cf` 打出上表产物。成功输出 `BUILD_OK`。

### 方式二：Maven

```bash
cd FmShop   # 或 FmKit
mvn package
```

`pom.xml` 以 `finalName = ${project.name}-${project.version}` 产出上表同名 jar。

### CI（`.github/workflows/build.yml`）

push 到 `main`、任意 PR、或打 tag 时触发：ubuntu-latest + Temurin JDK 25，按矩阵对 FmKit / FmShop 各跑一次 `mvn -B -ntp package`，各自 `target/*.jar` 上传为构件。tag 触发 GitHub Release：`v*` 前缀发布 FmKit，`shop-v*` 前缀发布 FmShop——一个插件的 tag 不会带出另一个的 jar。

### 部署

把对应 jar 放进服务端 `plugins/` 重启；升级直接覆盖。

## 自动化测试

两套 mineflayer 端到端套件都在 `bot/`：机器人真实进服操作 + RCON 驱动控制台，逐条输出 `PASS`/`FAIL`，结尾打印 `SUMMARY: 通过/总数`；存在失败时退出码 1，致命错误（`FATAL`）退出码 2。`HOST` 均固定 `127.0.0.1`，只打本机服务端；断言依赖服务端为**离线模式**（机器人无正版验证）。

通用准备：

1. 服务端 `server.properties`：`online-mode=false`、`enable-rcon=true`，端口与口令和套件默认值一致（或用环境变量覆盖；`fmtest123` 只是本地测试口令）。
2. 安装依赖（需要 Node.js）：`cd bot && npm install`。
3. 26.2 协议垫片：`mc_shim.js` + `static_ids_26.2.json`（minecraft-data 尚未收录的版本映射），两套件都经 `require('./mc_shim')(版本)` 启用；`captures_26.2.json` 为抓包样本。

#### 套件设计

- **基线复位**：每轮开头 op 机器人、两步确认清空公共箱、提醒档重置 `valuable`、到期去向重置转公共，消除跨轮残留；

### FmShop：fmshop_test.js（72 条断言，当前 72/72 通过）

```bash
cd bot
node fmshop_test.js
```

双客户端（默认 `FmShopper` + `FmShopMate`）对一台装着 FmShop 的 26.2 服务端实测：机器人点 GUI、跑玩家指令，RCON 负责 `give`/`fsa set`/`fsa reload` 等控制台动作。控制台侧另有纯 RCON 冒烟 `fmshop_console.js`（`RCON_PORT=25581 node fmshop_console.js`）。

环境变量（括号内默认值）：`PORT`（25580）、`RCON_PORT`（25581）、`RCON_PASS`（fmtest123）、`MC_VERSION`（26.2，须与服务端协议一致）、`BOT_NAME`（FmShopper）、`BOT2_NAME`（FmShopMate）、`DATA_DIR`（默认 `../servers/shoptest/plugins/FmShop`）。

服务端要求：装好 FmShop；离线模式；RCON 开启且口令匹配；两个机器人保持非 op（X1 专门断言非 op 玩家调 `/fsa` 被权限拦截）；`DATA_DIR` 必须指向被测服务端的 FmShop 数据目录——套件要直接读审计账本、改写 prices.yml。

#### 覆盖（组号即断言前缀）

- T0 双客户端进服；B 余额查询与余额不足拒绝；
- G1-G7 hub/分类页布局；G8-G16 确认页购买与 max 数量钳制；G17-G18 Shift+右键倾售整组；G19-G23 一键回收预览与确认；
- S 卖出：`sell hand`（含 5% 手续费）、`sell inv` 批量、空手/空包/创造模式拒绝；
- P 转账（含 2% 手续费，自转/低于下限/余额不足拒绝）；
- M 动态行情（买入推高报价、`fsa market reset` 回基线）；
- Q 每日限售（钳制到当日额度、售罄拒绝、`fsa resetlimit` 重开）；
- D 持久化（`fsa reload` 后余额不变）与审计账本（BUY/SELL/PAY 行落 `audit/<日期>.log`）；
- X 权限隔离（非 op 玩家调 `/fsa` 被拦、控制台可调，非 op 仍可正常购物）；
- W 深分页（装饰 221 件 = 5 页 × 45，末页翻页钳制）；
- E 附魔书 9 项（E1-E9，见下）。

#### 附魔书组（E1-E9）

- E1 hub 出现 附魔 分类，lore 标注 128 种商品；
- E2 附魔 页恰好 128 行且全是 enchanted_book（128 行共享同一 Material，靠 ItemKey 区分）；
- E3 每行有价，买价恒为卖价 6 倍（`buy-multiplier`）；
- E4 未卖出的行全部渲染为未解锁 + 终身可卖 1，直接买被「尚未解锁」拒绝；
- E5 与行精确匹配的锋利 V 书按本行价卖出（净得 = 卖价 × 0.95）；
- E6 第二本同种书被「终身限售」永久拒绝；
- E7 卖出后解锁购买，买回的书经原版 `clear <目标> <谓词> 0` 校验确为锋利 V；
- E8 多带一条附魔的书（锋利 V + 耐久 III）不匹配任何行，报「不回收」；
- E9 `/fsa price` 拒绝改生成行，提示去 prices.yml 的 `enchanted-books` 区段改价。

#### 运行副作用（都会动服务端数据，跑完恢复，别在生产服上跑）

- 限额组把 `DATA_DIR/prices.yml` 里 DIAMOND 的 `daily-sell` 改写成 2，结束后恢复为 256 并 `fsa reload`——一次运行会改写再还原该文件；
- 开局把难度切到 peaceful（防怪物杀机器人毁掉断言），结束恢复原难度；
- 过程中会清机器人背包、`fsa set` 改余额、`fsa resetlimit`/`fsa resetunlock` 重置限额与附魔书解锁计数。
